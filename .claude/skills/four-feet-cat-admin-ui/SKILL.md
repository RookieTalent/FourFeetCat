# FourFeetCat 管理台 UI Skill

管理台是 FourFeetCat 的**只读**操控面：跑在 `/admin` 子路径下的单页应用，自己没有后端——每一页只调一个已发布的只读 GET 端点，
把 JSON 渲染成表或文本。本 skill 的唯一价值是把"它长什么样、怎么搭"钉死，避免每次生成都重新发明一套视觉与工程习惯。

## 什么时候用

- 生成整套只读管理台（第26节做过一次）
- 给管理台加一个页面（第30节的"Agent 管理"页就是这么加的）
- 管理台视觉调整、接入新端点的展示

## 一、设计 token（唯一来源：官网首页当前样式定义）

取值**逐项照抄** `website/.vitepress/theme/styles.css` 的 `:root` 变量，不在本文件之外自创色值。官网改版后**先改首页、再同步本表**，
两处不一致就是漂移的开始。

| 用途 | 取值 | 说明 |
|------|------|------|
| 页面底色 / 卡片 | `#FFFFFF` / `#FFFFFF` | 明亮白底 |
| 浅色片底（表头、悬浮块） | `#F2F7FF` | 极浅蓝白片色 |
| 主色（激活项、链接、数值高亮） | `#3D6FD6` | 猫蓝；**仅用于强调，不铺大面积** |
| 副色（渐变、次级强调） | `#6EA8E6` | 浅空蓝 |
| 描边 / 分隔线 | `#E3EAF5` | 细描边；表格行分隔也用它 |
| 文字：主 / 次 | `#1E293B` / `#5B6B84` | 墨字 / 灰蓝字 |
| 阴影 | `0 10px 34px rgba(30, 64, 140, 0.08)` | 卡片用 |
| 正文字体 | `'PingFang SC','Microsoft YaHei','Noto Sans SC','Segoe UI','Helvetica Neue',Arial,sans-serif` | 中文优先 |
| 等宽字体（代码 / 会话 ID / JSON） | `ui-monospace,'JetBrains Mono','Cascadia Code',Consolas,monospace` | 标识类一律等宽 |

状态色（不在首页 token 内，是管理台自己的语义色，取常规语义值即可）：成功绿、失败红、警告橙；用**小圆点 + 文字标签**表示，不用整行染色。

## 二、工程约定（这几条错了页面就挂）

1. **`vite.config` 必须设 `base: '/admin/'`**，`build.outDir` 指向 `../resources/static/admin`（相对 frontend 目录），产物由 Spring 直接托管。
2. **产物不入库**：`fourfeetcat-web/src/main/resources/static/` 加进 `.gitignore`；源码与 `package-lock.json` 入库（`npm ci` 需要锁文件）。
3. **SPA 前端路由**：用 history 模式；服务端已有资源解析器把未命中的**非静态路径**回落到 `index.html`，所以刷新子路由不会 404。
4. **只调 `/api/v1` 下的只读 GET 端点**，且**只调已发布的那些**。管理台没有自有后端——它调不动某个端点，说明端点设计缺了一块，
   该去补端点（或确认它不属于本节范围），**不要**在管理台里直连数据库或绕开 API。
5. **只读**：不出现任何新建 / 编辑 / 删除 / 启停入口。要写操作先问端点存不存在（写端点是后续节的正题）。
6. **错误处理**：所有响应都是统一信封 `{code,message,data,timestamp}`；页面显示 `message` 字段，不要把 HTTP 状态码直接怼给用户。
7. **构建串联**：`frontend-maven-plugin` 绑进 Maven 的 `generate-resources`（`install-node-and-npm` 固定版本 + `npm ci` + `npm run build`），
   这样 `mvn clean package` 一条命令产出含管理台的产物。副作用：本模块的每次 Maven 构建都会跑一次前端构建，首次需联网。

## 三、布局与组件规范

```text
┌─ 顶栏：/logo.svg + "FourFeetCat 管理台" ─────────────────────┐
│ ┌─ 左侧竖直导航 ──┐ ┌─ 内容区 ────────────────────────────┐ │
│ │ 会话列表         │ │ 页面标题 + 一句说明                    │ │
│ │ Agent 列表       │ │ 表格 / 文本块 / 状态卡片                │ │
│ │ 工具列表         │ │ 加载中 / 空数据 / 出错 三态占位          │ │
│ │ 长期记忆         │ │                                     │ │
│ │ 运行状态         │ │                                     │ │
│ └─────────────────┘ └─────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

- 导航项：激活项用主色文字 + 左侧细竖条或浅色片底；未激活用次级文字色。
- 表格：表头浅蓝片底（`#F2F7FF`）、行分隔 `1px #E3EAF5`、悬浮行加极浅底；标识类列（会话 ID、工具名）用等宽字体；超长文本截断 + `title` 提示。
- 状态列：小圆点 + 文字（活跃 / 已归档），不要只用颜色区分（色盲不可辨）。
- 卡片：白底 + `1px #E3EAF5` + 圆角 6px + 阴影；**圆角只在小范围（4–6px）**，不要大圆角。
- 留白充足、层级靠间距与浅底区分，不靠重描边；整体克制，跟官网首页一个气质。

## 四、三态与响应式（缺一不可）

| 状态 | 要求 |
|------|------|
| 加载中 | 该页区域显示明确的加载占位（骨架屏或一行文字），**不白屏** |
| 空数据 | 明确空态文案（例："还没有会话"），不要渲染空表头 |
| 出错 | 显示信封里的 `message` + 重试按钮；不要把异常对象/堆栈渲染出来 |
| 窄屏 | 导航收起为顶部下拉或图标栏；表格允许横向滚动，不要挤成两行一字 |

## 五、验收清单（生成完逐条过）

- [ ] `/admin` 与每个子路由**直接访问与刷新**都能正常渲染
- [ ] 五（或 N）个页面都渲染**真实数据**（不是硬编码样例）
- [ ] 三态齐备：把网络断掉 / 数据清空 / 首屏加载各看一次
- [ ] 页面里**没有任何写操作入口**
- [ ] 颜色、字体、圆角与官网首页对得上（逐项对照第一节的 token 表）
- [ ] 窄屏（浏览器缩到 ~375px）不塌、不横向溢出
- [ ] `npm run build` 产物落在 `static/admin/`，且未被 `git status` 列为待提交
- [ ] `mvn clean package` 一条命令能产出含管理台的产物（构建插件已接好）

## 六、常见坑

| 坑 | 症状 | 正解 |
|----|------|------|
| 自创色值 | 管理台与首页两套气质 | 回到第一节的 token 表，缺哪个补哪个（并考虑是否该同步给首页） |
| `base` 没设 `/admin/` | 页面白屏、资源 404（请求打到了根路径） | `vite.config` 里设 `base:'/admin/'` |
| 产物入库 | 每次构建都产生一堆 diff，review 被淹没 | `.gitignore` 排除 `static/` |
| 前端路由回落写成了 API 也回落 | 接口路径打错返回一份 HTML，客户端解析 JSON 失败 | 回落只覆盖 `/admin/**` |
| 用外部 UI 组件库 | 视觉立刻偏离 token，且带进一堆用不上的依赖 | 手写少量组件（表、状态点、卡片）；确需组件库只选能被 token 完全覆盖的 headless 方案 |
