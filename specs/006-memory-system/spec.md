## User Scenarios & Testing *(mandatory)*

### User Story 1 - 三档长期记忆后端收敛到同一个门面之下，一行配置换实现 (Priority: P1)

Agent 要能记住跨会话的事，而"记忆存在哪"会随规模变：量小的时候一个 Markdown 文件最省事、人还能直接打开看；量大了要按分区结构化查；真需要自动提炼与语义召回时，该接一个可自托管的外部记忆服务。这三档不该让上层反复返工——上层只认一个门面，门面之下换个后端，上层代码与测试一行都不用改。

**Why this priority**: 这是本节的全部价值所在。第21节评审把方向定成"先把记忆焊成一个稳定接口，比先选存储形态更重要"；本节如果只交付"一个能用的文件式记忆"，那道墙就还是纸上的一句话——只有同一套上层代码、同一套契约测试真的在三档后端上都跑过，才能证明"接口不变、实现随便换"不是口号。

**Independent Test**: 三档后端分别装配进同一个门面，跑同一套用例——写入、取上下文、检索结果都对；再把配置项在三档之间切换，断言上层侧（组装器、记忆工具）零改动。

**Acceptance Scenarios**:

1. **Given** 已配置"文件档"，**When** 记一条再取上下文，**Then** 内容出现在返回的记忆上下文里，且人可以直接打开该文件读到同一条。
2. **Given** 已配置"结构化库档"，**When** 做与上一条完全相同的调用，**Then** 得到语义相同的结果，上层调用代码一字未改。
3. **Given** 已配置"外部服务档"（自托管实例），**When** 记一条并取上下文，**Then** 该档把三个操作翻译成外部服务的写入/读取/检索调用，底座侧接口不变。
4. **Given** 配置的是一档外部服务、但地址没配，**When** 启动并调用，**Then** 得到明确报错，不是静默成功。
5. **Given** 上游把配置从"文件档"改成"结构化库档"，**When** 重启后再对话，**Then** 既有记忆条目仍在、上层零改动，只有归档区"保留最近若干条"的落地方式由字符串裁剪变成查询条数上限。

---

### User Story 2 - 核心记忆始终在场，归档记忆可截断、可检索 (Priority: P1)

最影响体感的一件事是"Agent 每次都记得你是谁"。用户是谁、项目背景、关键偏好这类内容必须每轮完整在场，不能因为攒得多了就被裁掉、也不该参与"检索"（它本来就在）。而按时间累积的流水则相反：攒到一定规模只带最近一段，需要翻旧账时再按关键词去归档区里找。

**Why this priority**: 这是记忆能不能被信任的底线。核心记忆一旦被截断或检索不到，"始终在场"就是空话；反过来，归档区不做截断、不区分分区，迟早把上下文撑爆。两个分区的语义错了，三档实现再漂亮也没用。

**Independent Test**: 往核心区写一条、往归档区灌足够多内容触发截断，然后取上下文：断言核心那条一字不少还在、归档最早的已被裁掉、最近的在；再断言关键词检索只命中归档区、核心区不参与。

**Acceptance Scenarios**:

1. **Given** 一条写进核心区的记忆，**When** 归档区已远超截断水位，**Then** 取上下文时核心记忆完整在内（一字不少）。
2. **Given** 归档区写入量远超水位，**When** 取上下文，**Then** 只保留最近的内容，更早的被裁掉。
3. **Given** 一条只写在核心区的记忆，**When** 按它的关键词检索，**Then** 不返回它（核心区不参与检索），但它在取上下文时依然完整出现。
4. **Given** 同一关键词在归档区有多条命中，**When** 检索，**Then** 返回全部命中的归档条目。
5. **Given** 一次写入，**When** 紧接一次取上下文或检索，**Then** 新写入的内容立即可见（不许有进程内缓存）。
6. **Given** 长期记忆文件还不存在（首次运行），**When** 取上下文，**Then** 返回两个空区块、不报错。

---

### User Story 3 - Agent 自己动手记与查，走与内置工具完全相同的管道 (Priority: P1)

写入时机永远由 Agent 判断——它觉得某件事值得长期记住就记一条，需要回忆细节就按关键词查一下。这两个能力必须是"Agent 在对话里真能调到的工具"，与读文件、跑命令这些内置工具一视同仁：同一套注册管道、同一套执行与留痕路径、同一套按 Agent 工具清单过滤的机制。

**Why this priority**: 记忆的写入入口只有这一个（系统不做自动提炼），没有它，前面两档后端就是一段没人写的代码。而"走同一套管道"决定了加这个能力的成本——若记忆工具要另建注册机制，第20节验证过的"加一个工具的成本恒定在写一个类"就破了。

**Independent Test**: 两个记忆工具当普通内置工具注册进注册表，断言它们出现在"按 Agent 工具清单过滤"的结果里、调用后长期记忆本体真被改写、每次调用都落既有留痕路径；再断言分区参数缺省时写进归档区、取值非法时明确报错点名且不落库、检索未命中时返回明确结果而不抛异常。

**Acceptance Scenarios**:

1. **Given** 一个声明了记忆工具的 Agent，**When** 它在对话里要求记一件事，**Then** 内容被写入长期记忆，工具返回明确的成功结果。
2. **Given** 调用"记一条"时只给了内容、没给分区，**When** 执行，**Then** 写进归档区（缺省归档）。
3. **Given** 调用"记一条"时显式指定核心区（含大小写不一致的写法），**When** 执行，**Then** 写进核心区。
4. **Given** 调用"记一条"时分区取值不是核心/归档，**When** 执行，**Then** 返回点明该取值的明确错误、且长期记忆未被改写。
5. **Given** 一个关键词在归档区没有任何命中，**When** 调用检索，**Then** 返回"没有找到相关记忆"这类明确结果，**MUST NOT** 抛异常。
6. **Given** 任一次记忆工具调用，**When** 观察留痕，**Then** 成败都落在既有留痕路径上（**MUST NOT** 新建审计表）。
7. **Given** 一个 Agent 的工具清单里没有记忆工具，**When** 过滤可用工具，**Then** 它拿不到这两个工具。

---

### User Story 4 - 记忆进得了系统提示，且不重复注入历史 (Priority: P2)

组装每轮请求时，要把门面给出的记忆上下文注入系统提示，让 Agent"开口之前就已经知道"。同时守住一条：会话历史本来就有独立的一段在负责，记忆这一段**不能**再拼一遍历史——两份历史既浪费上下文，也会让模型看到前后矛盾的时间线。

**Why this priority**: 它是"记忆真正生效"的最后一公里，但依赖前三条先成立；而且它是唯一会触碰第17节既有组装逻辑的一处，回归风险要单独盯住。

**Independent Test**: 装配一个返回固定内容的门面替身，断言系统提示里出现了它、会话历史只出现一次；再断言未装配门面时组装结果与第17节基线逐字一致。

**Acceptance Scenarios**:

1. **Given** 已装配门面且记忆上下文非空，**When** 组装一轮请求，**Then** 系统提示里包含该记忆内容。
2. **Given** 记忆上下文为空（首次运行、尚无任何记忆），**When** 组装，**Then** 记忆那一段整体跳过，**MUST NOT** 注入空段落。
3. **Given** 一次组装，**When** 检查消息序列，**Then** 会话历史只出现一份（记忆段不重复注入历史）。
4. **Given** 未装配门面的装配方式，**When** 组装，**Then** 结果与第17节基线逐字一致（回归点）。

---

### Edge Cases

- **首次运行、记忆文件还不存在**：视为"两个分区都是空"，取上下文返回两个空区块、检索返回空列表，**MUST NOT** 报错；首次写入时把文件与两区块结构补上（并创建缺失的父目录）。
- **记忆文件缺分区标题**（被人手改过、或由工作区初始化生成的占位正文）：缺失的分区按空处理，**MUST NOT** 因格式问题让整轮对话失败。首次写入后文件被规范化成两区块形态——初始化模板里的占位说明文字因此**不被保留**，这是参考实现同款行为，属有意为之。
- **归档区为空时检索**：返回空列表（不是错误）。
- **同一关键词跨档命中口径**：文件档按行包含匹配（区分大小写）、结构化库档的库内匹配对 ASCII 不区分大小写——**两档在这一处不一致是已知状态**，本节不统一（跨档统一登记为后续节的修订）；因此契约测试**不对大小写行为下断言**。
- **关键词含库匹配的通配符字符**（`%`、`_`）：结构化库档按课件用 `LIKE` 字面拼接，本节**不**做转义处理——记忆是 Agent 自己写的内容，非对抗输入；此取舍写进实现注释。
- **单条记忆比截断水位还长**：截断后该条可能被切成半截——这是简单截断的已知代价，本节接受（记忆压缩在明确不做之列）。
- **写入失败（外部服务档不可达 / 库不可写）**：向上抛错，由工具执行路径记成失败的调用结果回填给模型换招，**MUST NOT** 静默当作写入成功。
- **读取失败（外部服务档超时 / 文件不可读）**：向上抛错，**MUST NOT** 静默返回空——静默为空会让 Agent 误判"没有任何记忆"。
- **外部服务档的地址未配置**：调用即明确报错（HTTP 客户端在缺少主机时会直接失败），**MUST NOT** 落明文默认地址。
- **外部服务档返回体不含期望字段**：解析后返回空列表，不抛异常（响应结构随该服务版本而异）。
- **长期记忆本体与用户手写的只读初始设定是两个文件**：全节所有读写路径都**MUST NOT** 触及后者。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 记忆门面 MUST 是放在契约层（core）的**跨模块契约**：上层（组装请求的一方、把记忆暴露给模型的一方）只认这一个门面，**MUST NOT** 分别去问会话存储与长期记忆本体两处；门面留契约层而非实现模块，理由 MUST 记入类注释（组装器在契约层、必须注入它，接口留在实现模块会成环；同第16节"Provider 服务接口上移"的既有手法）。
- **FR-002**: 门面 MUST 暴露三件事：①本轮要注入系统提示的记忆上下文；②"记一条"（内容 + 分区）；③"按关键词查一下"。这三个操作的名字与语义本节定死（接口墙），后续升级存储形态 **MUST NOT** 改动它们。
- **FR-003**: 长期记忆 MUST 抽成一个后端接口（对下可插拔，落实现模块），三档实现各写各的，**MUST 共用同一套行为契约**（见 FR-004~FR-008）。
- **FR-004**: 长期记忆 MUST 分为"核心"与"归档"两个分区；写哪个分区由调用方显式指定，缺省归档。系统 **MUST NOT** 猜测、**MUST NOT** 自动判定分区。
- **FR-005**: 核心分区 **MUST** 始终完整注入（"始终在场"），**MUST NOT** 参与截断，**MUST NOT** 参与关键词检索。
- **FR-006**: 归档分区超水位时 **MUST** 被截断、只保留最近内容；该截断 **MUST NOT** 影响核心分区。水位按档取值：文件档按字符、结构化库档按条数。
- **FR-007**: 长期记忆 **MUST NOT** 做进程内缓存：每次取上下文与检索都重新读取（文件 / 库 / 外部服务），使"记完下一轮立刻可见"成立。
- **FR-008**: 检索 **MUST** 是简单关键词匹配、**只在归档分区内**进行；**MUST NOT** 引入正则、分词或向量检索。大小写口径**按课件逐字**（文件档按行包含、结构化库档库内匹配、外部服务档用它自带的检索），本节**不做**跨档统一。
- **FR-009**: 系统 MUST 提供文件档实现（默认）：底层是工作区内 `memory/MEMORY.md` **一个** Markdown 文件（本节为工作区全局单份），以两个固定分区标题组织，每条记忆带日期；文件或父目录不存在时按空/创建处理；**MUST NOT** 新增任何第三方依赖。
- **FR-010**: 系统 MUST 提供结构化库档实现：记忆按条入库（分区、内容、时间）；核心区按写入顺序全量取、归档区取最近若干条（查询条数上限，**不是删除**）、检索走库内匹配。**MUST 复用**既有数据库与既有迁移机制；**MUST NOT** 引入新的第三方依赖。
- **FR-011**: 系统 MUST 提供外部记忆服务档实现：以**自托管**服务为后端，三个操作翻译成它的写入 / 读取 / 检索调用；地址与作用域标识 **MUST** 走环境变量占位，**MUST NOT** 落明文；提炼、冲突消解、语义召回交给该服务，底座侧契约不变。
- **FR-012**: 三档 MUST 由同一个配置项选择（文件档为默认，取值逐字为 `markdown` / `sqlite` / `mem0` 三选一）；切换后端 **MUST 只改配置**，**MUST NOT** 改门面以上的任何代码。外部服务档的地址与作用域标识 MUST 是同一配置族下的独立键。
- **FR-013**: 系统 MUST 提供两个内置工具把长期记忆暴露给 Agent：①"记一条"（参数：内容 + 分区）②"按关键词检索"。分区参数缺省取归档、取值大小写不敏感归一；取值非法时 **MUST** 返回点明该取值的明确错误且 **MUST NOT** 改写记忆；检索未命中时 **MUST** 返回"没有找到相关记忆"这类明确结果，**MUST NOT** 抛异常。
- **FR-014**: 两个记忆工具 **MUST** 走与既有内置工具完全相同的注册管道、过滤机制与留痕路径（成败都留痕）；**MUST NOT** 另建注册机制，**MUST NOT** 新建审计表。
- **FR-015**: 组装请求时 **MUST** 经由门面取得记忆上下文并注入系统提示；会话历史 **MUST** 仍由既有的历史段独立负责，**MUST NOT** 重复注入两份历史；记忆上下文为空时该段整体跳过。未装配门面时组装结果 **MUST** 与第17节基线逐字一致。
- **FR-016**: 全节所有读写路径 **MUST NOT** 触及用户手写的只读初始设定文件；可被 Agent 写入的只有长期记忆本体。
- **FR-017**: 会话记忆的读写 **MUST** 仍由既有会话管理者承担，**MUST NOT** 迁入本门面；会话标识的拼接口径 **MUST** 保持不变（仍只在一处生成，本节不改）。门面本节**只**承载长期记忆的三个操作；会话历史与长期记忆由组装器一并注入系统提示（分工见 FR-015）。
- **FR-018**: 记忆工具的执行留痕 **MUST** 与既有工具逐字段同口径（同一张表、同一组字段、同一份成败判定），本节 **MUST NOT** 新增任何审计字段或审计逻辑。可验证形式：调用一次记忆工具后，审计表里出现且仅出现一行、字段完整（这是 SC-005 的承载条款，不是 FR-014 的重复——FR-014 管"走哪条管道"，本条管"留痕内容的完整性"）。
- **FR-019**: 装配 MUST 在既有装配类内完成（**MUST NOT** 新建自动配置文件）：按配置造出被选中的那一档后端、包成同一个门面、注入组装器与工具注册表；并 MUST 把记忆模块接入可运行产物（否则新类既进不了容器也进不了打包产物——同第19节"不接上则 @Component 成死注解"的既有教训）。
- **FR-020**: 交付一档**内存后端**实现（进程内 Map，满足四条契约），用途有二：作为"同一套契约断言对三档统一跑"中**外部服务档的替身**（真实 REST 交互由该档专属测试单独验证），以及作为门面与工具测试的轻量基建。该件超出课件"本节交付物"清单，**经主公追认后交付**。
- **FR-021**: 表结构变更 MUST 走既有迁移机制的双轨目录（同版本号、只增不改），脚本内容 MUST 与课程参考建表脚本中该表的定义一致。

### Key Entities *(include if feature involves data)*

- **记忆上下文**：本轮要注入系统提示的那一段文本——核心分区全量 + 归档分区截断后的内容。不是持久化数据，是每次现取的一份视图。
- **长期记忆条目**：一条被记住的事——内容 + 分区（核心 / 归档）+ 时间。存储形态随后端而变（文件里是一行带日期的条目、库里是一行记录、外部服务里是它自己的一条记忆）。
- **记忆分区**：核心（始终在场、不截断、不检索）与归档（按时间累积、可截断、可检索）。这是跨三档不变的语义，不是某个后端的实现细节。
- **长期记忆本体**：工作区内的那一个记忆文件 / 那一张记忆表 / 那一个外部服务上的记忆集合——三档各自一份，同一时刻只有被配置选中的那一份生效；本节为工作区全局单份。
- **后端选择配置**：决定装配哪一档的配置项（默认文件档），外加外部服务档自己的地址与作用域标识两个键。
- **模块职责标记类**：记忆模块的说明性标记类（该件超出课件清单，经主公追认后交付）。
- **用户手写的只读初始设定**：与长期记忆本体并列的另一个启动信息文件，用户手写、底座只读——**不是**本节的写入对象。

## Success Criteria *(mandatory)*

- **SC-003**: 写入后到下一次取上下文可见之间的等待轮数为 **0**（不缓存契约的可测形式：写完立刻取，必命中）。

- **SC-005**: 记忆工具调用的留痕覆盖率为 **100%**，本节新增审计表 **0** 张。
- **SC-006**: 未装配门面 / 记忆上下文为空两种情形下，请求组装结果与第17节基线的差异字符数为 **0**。
- **SC-007**: 关键词未命中场景的明确返回率为 **100%**，抛异常次数为 **0**；分区取值非法场景的"点明取值且不改写记忆"率为 **100%**。
- **SC-008**: 只读初始设定文件被写入的次数为 **0**（全节代码路径核对）。
- **SC-009**: 可自动化验收由课件"验收 harness"承载（`mvn test` 全绿即通过），测试类清单：契约测试（参数化遍历三档：文件档 / 结构化库档 / 内存替身档，同一套断言全过——写后立读、截断只裁归档区且核心一字不少、分区路由正确、检索只搜归档区）；文件档专属（空文件、截断边界、区块解析、写入不串区）；结构化库档专属（归档条数上限只加在归档查询、检索只命中归档）；外部服务档专属（以进程内假服务断言写入请求体带内容与分区、检索被转发并解析、服务端 5xx 异常上抛不静默吞）；记忆工具（分区缺省归档、显式核心、非法分区点名报错且不落库、未命中友好提示）；门面（取到的上下文含核心全量 + 归档截断且核心完整在内、记与查转发到后端）；仓储（迁移脚本建出的表能存能读、归档条数上限生效、库内匹配只命中归档）。

## Assumptions

- **对账基准（已裁决）**：本节交付面**严格对齐参考实现第22节那一版**（其文件清单与课件"本节交付物"逐条成对）。因此：长期记忆为**工作区全局单份**；检索大小写**不统一**（登记为后续节修订）；按 Agent 隔离**不在本节**（登记为后续节，参考实现自述该能力属"Agent 专属记忆"）。
- **门面落点（已裁决）**：门面接口与分区枚举落 `core` 的 memory 包（跨模块契约层），实现在记忆模块；这与课件"上层只认门面"一致，也是参考实现的既有手法（同第16节"接口上移"，理由是避免 core → 实现模块成环）。
- **接缝形态（已裁决）**：第17节组装器的第二构造参数由"按 Profile 供给的一段文本"改为**直接注入门面接口**；未装配门面时该段留空；单参构造保留（未启用记忆的路径一字不变），其既有测试随之调整断言写法。这是本节唯一触碰前序节公共接口之处，理由记入 plan。
- **门面语义（已裁决）**：门面取上下文的操作**只返回长期记忆**（核心区全量 + 归档区截断后），**不**拼会话历史——harness 表格为准；会话历史归既有历史段独立负责。
- **持久化落点（已裁决）**：`memory_entries` 表的实体、仓储与迁移脚本全部落存储模块，与既有四张表同址同口径（双轨目录、同版本号、只增不改）；记忆模块加一条对存储模块的依赖（无环）。迁移脚本内容逐字取自课程参考建表脚本中该表一段。
- **配置键（已裁决）**：顶层 `memory.backend`（取值 `markdown` / `sqlite` / `mem0`，默认 `markdown`）、`memory.mem0.base-url`（从环境变量读、缺省空）、`memory.mem0.user-id`（从环境变量读、缺省 `fourfeetcat`）。这是参考实现的既有形态，与 `fourfeetcat.providers` 一族并存。
- **额外交付物（已裁决）**：内存后端实现与模块职责标记类两件超出课件清单，经主公追认后交付；同时交付参考实现有、课件清单未列的仓储测试。
- **命名口径**：课件 OryxOS 命名统一映射 fourfeetcat（模块名、包名、工作区 `.fourfeetcat/`、`FOURFEETCAT_ROOT`）；配置键按上条逐字保留顶层形态（参考实现既有形态，不改名）。
- **水位与格式取值**：文件档按字符（4000）、结构化库档按条数（最近 100 条）、内存后端按条数（最近 100 条）——三者口径不同是有意为之（字符串裁 vs 查询条数上限）。文件档条目行形如 `- [日期] 内容`；结构化库档渲染条目行为 `- 内容`。两者渲染形态不同不改。
- **错误口径**：写入失败向上抛错（不静默成功）；读取失败向上抛错（不静默返回空，避免"没有任何记忆"的误判）；"未命中"与"读取失败"是两件不同的事，前者返回明确提示、后者抛错。
- **外部服务档的范围**：只做协议转换（三个操作 ↔ 外部服务的写入 / 读取 / 检索），提炼、冲突消解、语义召回都由该服务承担；本地无实例，真连属人工确认项。端点路径按该服务的社区版约定编写，具体以其部署版本为准（写进实现注释）。
- **依赖前序节交付物**：`Profile` 与注册表、`Session` 与 `SessionManager`（第16/18节）、组装器与其记忆接缝（第17节）、工具注册表与内置工具注册管道（第20节，已为记忆工具留好注册位并用替身工具验证过四步）、工具执行留痕（第17节）、双轨迁移机制与默认数据库（第18/19节）、工作区路径与初始化模板（第18节）。
- **外部依赖**：需在锁定依赖清单里核实到本模块要用到的 API（Spring AI 的工具注解与参数注解、同步 HTTP 客户端、Spring Data 分页类型、以及持久化注解）确实存在且可下载；核实不到即停下报告，**MUST NOT** 自行换依赖。参照参考实现，记忆模块新增依赖为：存储模块、`spring-web`、Spring AI 工具注解所在构件；**MUST NOT** 引入新的第三方库。
- **静态检查**：SpotBugs（高强度、低阈值）可能对"构造器持有注入的协作者引用"报出暴露内部表示的告警；处理方式必须在 plan 中显式选择（注解抑制或既有排除清单），**MUST NOT** 通过放宽全局门禁绕过。
- **审计口径**：记忆工具的执行走既有执行路径，成功失败都留痕；本节不新增审计逻辑、不另建审计表（宪法原则五）。
- **范围边界（课件"有几样先别做"）**：①"记一条"的自动触发（核心阶段写入时机永远由 Agent 判断）②从对话历史自动抽取记忆 ③结构化矛盾检测 ④记忆压缩 ⑤知识图谱后端 ⑥进程内自建向量层 / 语义检索 ⑦情景记忆 ⑧按条编辑与删除记忆的 CRUD 接口。另按对账结论，**按 Agent 隔离**与**跨档统一检索大小写**也不在本节。
