- Q: 是否本节一并交付 SMTP 端点白名单？（课件本节只交付文件/命令/域名三类校验与三个配置键；技术方案 §6.7、宪法原则六、CLAUDE.md 都列了第四个 `smtp.allowed_endpoints`；但第20节已定死的动作类型枚举里没有 SMTP 取值，且邮件通知实现标注为扩展阶段、代码库中尚不存在。） → A: **本节不做**。动作类型枚举不动、不新增取值；SMTP 端点白名单随邮件通知实现一起落地。这处文档与代码的差登记在本节验收报告里，不静默。
- Q: 三个白名单配置键在默认配置里的初值怎么定？（课件只点名三个键存在，并要求把"空 = 什么都不允许"写进配置说明，未给默认值。） → A: **文件白名单默认 = 工作区根**，Agent 开箱只能碰自己的工作区；**命令与域名白名单默认为空 = 全拒**，由管理员显式放行（对齐"把解释器列入白名单是管理员的显式授予""数据不出域"两条既有口径）。

**第二轮（spec 定稿前的两处口径）：**

- Q: 域名比对是否考虑端口、路径与大小写？（例：白名单 `*.example.com` 收到 `https://API.Example.com:8443/x`。） → A: **只比主机名**——端口与路径不属"域名"白名单的管辖范围；**大小写敏感**，`API.Example.com` 不命中（与命令白名单同一口径：配什么写什么，不做归一）。
- Q: 白名单项本身是相对路径时怎么处置？（相对路径按当前工作目录解析，同一份配置在 CLI、守护进程、容器三处的工作目录各不相同。） → A: **启动即拒**——白名单是安全配置，语义必须与环境无关；配置校验发现非绝对路径即报错并点名该项，不启动、不静默变形。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 越界动作当场被拦，模型在下一轮自己换策略 (Priority: P1)

企业管理员给 Agent 配一份白名单：只能读写工作区、只能跑指定的几个命令、只能访问自家域名。Agent 在对话里生成的每一个涉外动作（读文件、跑命令、发请求）在真正动手之前先过这一道校验；越界的当场被拦下，且模型看到的是"为什么被拦"，不是"调用失败"这种废话——它据此在下一轮调整策略，而不是反复撞同一堵墙。

**Why this priority**: 这是本节的全部价值。没有它，第23节评审定的那道墙只是纸上的一句话；有了它，Agent 才敢被放进真实系统里干活。放行侧的正确性只是及格线，安全模块真正的验收标准是**绕不过去**。

**Independent Test**: 配一份只允许工作区、只允许一个命令、只允许一个域名的白名单，逐一构造越界输入（路径穿越、白名单外命令、白名单外域名、形似域名），断言每一次都被拦下且被拦原因点名了越界物；再断言白名单内的同类动作全部放行。

**Acceptance Scenarios**:

1. **Given** 白名单只含工作区根，**When** 请求读取工作区之外的文件，**Then** 动作被拦下，返回原因指明该路径不在白名单内。
2. **Given** 白名单只含工作区根，**When** 请求读取形如"工作区/../../外面"的路径，**Then** 同样被拦下（穿越不得绕过白名单）。
3. **Given** 工作区内有一个指向工作区之外的软链，**When** 请求读取该软链指向的内容，**Then** 被拦下（校验的是真实路径，不是字符串前缀）。
4. **Given** 命令白名单只有一项，**When** 请求执行白名单外的命令，**Then** 被拦下，原因里点名该命令。
5. **Given** 域名白名单含通配符 `*.example.com`，**When** 请求 `https://api.example.com/x`，**Then** 放行；**When** 请求 `https://evil-example.com/x`，**Then** 拦下（"以 example.com 结尾"不等于"是它的子域"）。

---

### User Story 2 - 被拦下的动作走的是同一条审计路径，运维查得动 (Priority: P1)

安全事件要能在事后被追溯：一次被拦下的动作必须和一次失败的工具调用一样，留下一条可查的记录（失败标记 + 人能读懂的原因）。这条路径**不许为沙箱另开**——一旦沙箱违规需要专门的处理逻辑，说明它没有被自然地融进既有的工具执行框架。

**Why this priority**: 可审计是本项目从第一天就立下的底线能力。安全模块尤其不能有"拦了但没留痕"的角落：拦下却没记录，等于事故现场没有脚印。

**Independent Test**: 让一次越界动作走完整的工具执行管道，断言审计里得到一条失败记录，原因是沙箱给出的可读原因；再断言放行的那一次走的是同一个记录入口（唯一差别是成功标记）。

**Acceptance Scenarios**:

1. **Given** 一次被白名单拦下的工具动作，**When** 它走完工具执行管道，**Then** 审计中得到一条失败记录，失败原因即沙箱给出的原因（如"命令不在白名单内: rm"）。
2. **Given** 一次被放行的工具动作，**When** 它走完同一条管道，**Then** 走的是同一个记录入口，唯一差别是成功标记为真。

---

### User Story 3 - 换更重的隔离只新增实现，上层一行不改 (Priority: P2)

将来要跑相对不可信的代码、要做多租户时，隔离强度要能升级到容器乃至 microVM。升级的方式必须是"新增一个实现类"：校验入口的抽象签名、四个已接线工具的调用代码、工具执行器与审计逻辑，一处都不改。这条不是功能，是**对已交付代码的承诺**，因此必须能被验证。

**Why this priority**: 第23节评审把这定为接口中立性的验收方式。如果本节的实现把"检查路径""检查命令"这类某一档专属的动作用法写进了对外契约，将来升级就得改接口、连带改所有调用方，第23节那道墙就白设计了。

**Independent Test**: 通读对外可见的契约（一个校验入口 + 动作类型 + 动作值对象 + 违规异常），确认其中不出现"白名单""容器""镜像"等某一档专属词；并确认在最重的 microVM 设想下，需要一个新实现时不需要给这个契约加任何方法。

**Acceptance Scenarios**:

1. **Given** 本节的实现类，**When** 检查对外契约的成员，**Then** 只有"校验一个动作"这一个入口；三个具体校验都是实现内部的事，不在契约上。
2. **Given** 设想一个 microVM 档实现，**When** 让它实现同一个契约，**Then** 不需要新增方法、不需要改调用方。

---

### Edge Cases

- **白名单配置项为空**：表示"什么都不允许"，而不是"不做校验"。空配置下所有同类动作都被拦下——安全模块的默认姿态必须是关着门。
- **命令带前导空格**：`"  ls"` 这类输入取首 token 前先去空白，避免用空格绕过白名单比对。
- **命令大小写变体**：按精确比对，白名单里写 `ls` 就不认 `LS`——白名单是管理员逐项列的清单，不做大小写归一（允许什么就写什么）。
- **域名匹配的口径**：只比主机名——端口与路径不参与比对（`https://api.example.com:8443/x` 命中 `*.example.com`）；大小写敏感（`API.Example.com` 不命中）。`*.example.com` 命中 `api.example.com`，不命中 `example.com`（裸域不在通配范围内），也不命中 `evil-example.com`。
- **相对路径的白名单匹配**：白名单根是绝对路径；相对输入应先解析成绝对路径再比对，否则同一个目录换个写法就绕过了。
- **白名单项写成相对路径**：启动即拒并点名该项——安全配置的语义不得随运行环境的工作目录变形。
- **路径的最近存在父目录**：写一个还不存在的新文件时，目标本身没有真实路径可解析，只能逐级上溯到最近存在的父目录，用它解析后的真实路径判断——否则"在白名单内建目录、目录里放软链、往软链里写"就能绕出去。
- **请求方给的不是合法 URL**：解析不出主机名的输入一律按拦下处理（解析失败不得当作放行）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 以唯一入口"校验一个动作"对外表达涉外动作的放行与否；上层只依赖这一抽象，不认识底下是哪一档实现。
- **FR-002**: 动作 MUST 携带类型与目标两项信息，且 MUST NOT 携带任一档实现特有的字段（如白名单、容器镜像、资源配额）。
- **FR-003**: 系统 MUST 按动作类型路由到三类校验：文件读与文件写共用同一份路径白名单、命令比对可执行文件白名单、请求做域名匹配。读与写 MUST 分开取值，以保留按读/写分权限的余地。
- **FR-004**: 路径校验 MUST 先做标准化以堵住路径穿越；目标已存在时 MUST 解析其真实路径（软链被解析后）并复验仍在白名单根之内；目标不存在时 MUST 对最近存在的父目录做同样的真实路径复验。
- **FR-005**: 命令校验 MUST 取首 token（去前导空白后）与白名单精确比对；命令与参数 MUST 以数组直传，不经 shell 解释（沿用既有实现，本节不改）。
- **FR-006**: 域名校验 MUST 支持精确项与通配项，MUST 只比主机名（端口与路径不参与比对），MUST 大小写敏感；通配项的匹配 MUST 带点号边界，`*.example.com` 命中子域但 MUST NOT 命中形似域名（如 `evil-example.com`），MUST NOT 命中裸域 `example.com`。
- **FR-007**: 校验不通过时系统 MUST 立即终止该动作（真实的 IO MUST 未发生）并抛出违规异常，异常原因 MUST 点明越界物与所属白名单类别。
- **FR-008**: 违规异常 MUST 走既有的工具执行失败审计路径落库（失败标记 + 可读原因），系统 MUST NOT 为沙箱新增独立的审计通路或数据表。
- **FR-009**: 四个已接线的涉外工具（文件、命令、请求、通知）MUST 在各自执行的最开头先校验、通过才动手；本节 MUST NOT 改动这一顺序与其余执行逻辑。
- **FR-010**: 三类白名单 MUST 从配置读取，键分别为文件路径、命令、域名；配置项为空 MUST 表示"什么都不允许"。适用于本节的默认配置：文件白名单默认取工作区根，命令与域名白名单默认为空。
- **FR-013**: 白名单配置 MUST 在启动时校验：文件白名单项不是绝对路径时 MUST 报错并点名该项、不得启动、不得静默按工作目录解析。
- **FR-011**: 系统 MUST NOT 使用 Java SecurityManager（该 API 在本运行时版本已不可用），隔离 MUST 由白名单校验实现。
- **FR-012**: 本节 MUST 移除第20节留下的临时装配（一个不做任何校验的占位实现），并以白名单实现承接同一个装配位，调用方零改动。

### Key Entities

- **待校验动作**：一次涉外动作的意图表达，含两项——动作类型（文件读 / 文件写 / 命令 / 请求）与目标字符串（路径、可执行文件名或完整 URL，由类型决定如何解释）。
- **白名单配置**：三组配置值——允许的文件路径根（绝对路径）、允许的可执行文件名（精确项）、允许的域名（精确项与通配项）；空 = 全拒。
- **违规异常**：校验不通过的唯一对外信号，携带可读原因；是工具执行失败的普通一种，不携带任何沙箱专属的处理分支。
- **校验档位实现**：本节交付的"应用层白名单"这一档，是契约在核心阶段的唯一实现；将来新增的容器档、microVM 档是同一契约的其它实现。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 三类校验各自"允许 + 拒绝"成对可测，且下面四个绕过场景全部被拦：相对路径穿越、软链指向白名单之外、形似通配域名的近似域名、白名单外的命令；四条断言全部通过。
- **SC-002**: 四个已接线工具各有一条回归用例，同时证明"越界输入被拦"与"危险动作真的没跑"（不只看异常，还看副作用：文件未被改动、进程未启动、请求未发出）。
- **SC-003**: 改造后四个工具原有的全部测试保持通过，零断言被删改、零用例被跳过。
- **SC-004**: 手工通读对外契约，其中不出现"白名单/容器/镜像/沙箱档"等某一档专属词；设想一个 microVM 档实现接入时，需要新增的对外方法数为 0。
- **SC-005**: 一次真实越界动作走完整链路后可被追溯：审计中存在一条失败记录，原因文本不出现"调用失败"这类无信息量表述，而是点名越界物。
- **SC-006**: 全量构建门禁（含静态检查与安全检查）在交付时全绿。
- **SC-007**: 配置里出现相对路径白名单项时，启动失败且报错点名该项（一条可测断言）。

## Assumptions

- 白名单由企业管理员手工维护，属于**可信配置**；本节的校验是"劝阻级"防线，防的是模型犯傻与误操作，防不住蓄意攻击——此局限 MUST 在配置说明里写明，核心阶段不建议用它跑完全不可信的代码或对外做多租户。
- 动作目标字符串由调用方（各工具）如实填写：文件工具传路径、命令工具传可执行文件名、请求与通知工具传完整 URL。校验只对"被交给它的目标"负责，覆盖不了"绕过工具直接动手"的路径（进程内直调、外部子进程等），这些是后续隔离档要收的暴露面。
- 白名单根一律是绝对路径（配置里写相对路径即启动拒绝，见 FR-013）；动作目标若是相对输入，按当前工作目录解析成绝对路径后再比对。
- 命令白名单的语义是"可执行文件名精确匹配"：把解释器（如 `sh`）列进白名单即等于管理员显式授予本机代码执行权限，不构成隔离。
- 依赖第20节已交付并在用的契约与调用位（本节不改其签名）、第19节的通知工具与渠道注册表、第17节的工具执行失败审计路径、第22节已就位的记忆工具（不改）。
- 默认配置下命令与域名全拒，因此开箱状态下需要网络或命令的能力要管理员显式放行才会生效；文件能力开箱限定在 Agent 自己的工作区内。
